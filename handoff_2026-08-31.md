### Ordering — complete, plan archived

Fractional `rank` is gone from the codebase: three columns, six indexes, the
`fractional-indexing` dependency, `lib/ordering.ts`, `lib/documentOrder.ts` and
most of `repositories/ordering.ts`. Order now lives in an array on the container
that owns the list, read through one tolerant reader (`src/lib/orderArray.ts`)
and written through four endpoints.

**Four arrays, not the three the plan specified.** `Project` owns its member
series' order *and* sits in the root list, so `User.rootOrder` interleaves ids
from three tables. The plan missed `Project` in both §2 and §4.

**The local library moved too**, so there is one ordering mechanism rather than
two. §7 had been deferred by phases 3 and 4; phase 5 could not defer it again.
A guest's root order is a keyval record in IndexedDB, a tabbed post's is
`tabOrder` on the post itself.

## Traps learned — worth carrying forward

1. **Prisma generates destructive SQL for column changes.** `DROP` + `ADD` for
   the `role` enum conversion (would have discarded every role) and for both
   phase B and C changes; C's would not even have run. **Three of the four
   schema changes across all four phases.** Hand-write the SQL and rehearse it
   against a restored copy.
2. **`tsc` has blind spots on a field rename.** Four breaks it could not see,
   all 500s on the main read path: two `as const` Prisma selects (validated only
   at query time), a `Record<string, unknown>` cast, and two `$queryRaw`
   templates. `grep -rn 'name: true'` and `grep -rn '\$queryRaw'` found them.
   "Let TypeScript surface the call sites" is necessary, not sufficient.
3. **An IndexedDB upgrade can lose data while looking like it worked.** The
   first `name → title` migration ran one cursor pass per version; three cursors
   on one store each held the record as they found it and took turns writing
   back, last write winning. A real profile came out with one of three renames
   applied *while the index swaps beside it succeeded*. Fixed by folding every
   crossed version into a single pass per store, with the transform exported so
   the spec drives the same function the browser does.
4. **`git status` hides untracked files in this repo**
   (`status.showUntrackedFiles=no`). 46 build-output files rode into `d458483b`
   because a dev server recreated `.next-verify` between the `rm -rf` and the
   commit. Kill the server *before* deleting its build dir, and check with
   `--untracked-files=all`.
5. **`:3000` is usually a stale `next start` production build.** Do not clobber
   it: `next.config.ts` reads `distDir` from `BUILD_DIR`, so
   `BUILD_DIR=.next-verify pnpm dev -p 300X` runs a dev server beside it.
   Afterwards revert `tsconfig.json`, which the dev server edits.
6. **Sidebar multi-select needs the modifier on every click.** Selection is
   `useRowSelection(ids, "clear")`, under which a plain click sets only the
   anchor. A plain-then-ctrl click selects one row and the drag silently carries
   one while looking like it carries two.
7. **`docker compose up -d` would kill the dev database.** `postgres-blog`
   (postgres:17.2) already serves 5432 with the real data; the repo's compose
   file defines a different service on that port.

## Bugs found in passing

- **`/api/import` could never import a new document.** It wrote each document's
  revisions before the row they point at, so the first hit
  `Revision_documentId_fkey` and the whole import failed. Pre-existing, silent,
  untested. Fixed as a side effect of phase B.
- **Creates did not maintain the store's order arrays.** Phase 4 added that for
  re-homes but left creates to the tolerant reader, so a `placement: "start"`
  post read *last* until the next load — invisible for a signed-in user because
  the server prepended and a reload settled it, not invisible for a guest whose
  store *is* the read. Fixed in phase 5.
- **`Document.parentId` would have been left with no index at all.** Its only
  one was the composite with `rank`, and "the children of this post" is a live
  query behind every tab strip. `Document_parentId_idx` added.
